# Week 2 Homework: A Fresh App, Deliberately Built

## Goal
Build a new application in a new GitHub repository using VS Code and your own agent. Week 1 was setup and exploration; do not simply submit that experiment again. There is no requirement to buy or switch to another agent.

## Choose a Scope
Choose your own small application: a reading tracker, quiz app, task board, study planner, or similar. Define one complete user workflow that can be finished in the time budget. Python or JavaScript/TypeScript are suitable; explain your stack choice.

## Requirements
- A working end-to-end user workflow with local persistence or equivalent saved state.
- A short written specification with observable acceptance criteria, including an invalid-input or error case.
- Project instructions that your agent actually consumes: purpose, relevant files, conventions, validation commands, and boundaries.
- One reusable skill/procedure with inputs, steps, and expected evidence. Use it at least twice and record what changed or stayed useful.
- Relevant automated checks plus a manual demonstration. Inspect generated code and explain one changed function.
- A README with exact setup/run/check commands and known limitations.

## Suggested Budget (5–10 hours)
Plan and set up (1–2h); build with short validation cycles (2–4h); test a failure case and refine the skill (1–2h); review and submit (1–2h). If core functionality is incomplete, state it clearly and show your investigation; optional polish does not replace required behavior.

## Evidence and Submission
Open a PR in your own repository. Link the specification, instructions, skill, and `docs/prompt-logs/week-02.md`. Use the shared [evidence-log template](../../../infrastructure/template/docs/prompt-logs/TEMPLATE.md), with an added “Week 1 vs. Week 2” comparison. Include a demo/screenshot, check results, a changed-function explanation, and a brief account of what you trusted, checked, and corrected. If no spontaneous failure occurred, deliberately challenge an assumption with a negative case; do not invent an AI mistake. Share the PR before the next class.

## Assessment
| Criterion | Weight |
|---|---|
| Working workflow and demonstrated acceptance criteria | 30% |
| Useful project context and reusable skill | 25% |
| Validation, code understanding, and justified correction | 30% |
| Specific Week 1 comparison and honest limitations | 15% |

Optional: a second workflow or accessibility improvements after the core checks pass.
