# Handoff: Weeks 1–4 to Production

## What Students Have Practiced
- **Week 1:** Three nontechnical builders' presentations and workflow stories, Q&A, at-home setup, and an exploratory attempt.
- **Week 2:** A fresh app in VS Code, prompt versus context, instruction layers, project instructions, a reusable skill, and in-the-loop validation.
- **Week 3:** One sustained terminal agent, verified context discovery, skills, checkpoint/resume, and on-the-loop supervision applied to an Excalidraw feature choice.
- **Week 4:** Script-driven, instruction-driven, and hybrid harness concepts; agent roles/connections; actual coordination and integration evidence in an open-ended hard build.

## Expected Evidence
GitHub repositories or forks with run instructions, task specifications, project guidance, reusable procedures, selected session/checkpoint excerpts, meaningful checks, working demonstrations, and explanations of what was trusted, verified, and corrected. Review incomplete criteria individually; do not assume every assignment is complete.

## Week 5 Entry Decision
The Week 4 application may continue if it fits the production objectives, or the student may start a new application. It is not necessarily a Python/SQL application. Carry forward the engineering methods even when starting a new repository.

Week 5 must explicitly establish the production baseline: approved domain, architecture decision, API contract, relational schema, initial migration, backend, and integrated frontend. Week 7 adds the data-preserving follow-up migration and PostgreSQL verification. Scope this to one working slice. Do not assume these artifacts were created during Week 4 orchestration.

## Production Sequence
| Week | Focus |
|---|---|
| 5 | Start or adapt the production project; establish architecture, database/migrations, API, and frontend integration |
| 6 | Strengthen failure-path tests, security checks, and quality gates |
| 7 | Validate PostgreSQL behavior and migrations; containerize and extend CI |
| 8 | Review IAM, secrets, and budgets; deploy |
| 9 | Diagnose an incident and verify a regression fix |
| 10 | Audit workflow evidence and test an improvement |
| 11 | Practice interviews and engineering explanations |
| 12 | Present the production project and a verified engineering case study |

## Assessment and Distribution
Budget 5–10 hours of homework per week. Week 1 uses its field-report rubric; Weeks 2–4 use their own homework weights with shared evidence guidance. All course material, including presenter notes and solutions, is shared through GitHub. Require disclosure of reuse and assess understanding rather than secrecy. Students arrive with GitHub accounts and their own paid agents supporting both VS Code and terminal use.
